A city about to receive the world

BelemConverse answers questions about where to go in Belém do Pará — in Portuguese or English, the way people actually ask them.

In November 2025 Belém hosted COP30, the United Nations climate conference, and tens of thousands of delegates, journalists and visitors arrived in a city most of them had never seen. They needed the same things everyone needs: somewhere open at this hour, somewhere close by, somewhere good. Search engines answer that question for São Paulo and Rio far better than they answer it for Belém.

That gap is what this project is about. BelemConverse reads a curated index of local places — the markets, the botecos, the açaí stands, the parks, the hotels — and answers in whichever language you asked. A visitor typing English gets English. A resident typing “cadê uma barbearia bacana aqui pertinho?” gets Portuguese, and gets understood.

When retrieval comes back empty, the agent asks a clarifying question instead of inventing a place. That behaviour is specified, not incidental.

How an answer gets made

Three stages, in a fixed order. The language model is only involved in the last one.

Plan

A TF-IDF intent classifier turns the message into a structured query plan: what kind of place, whether opening hours matter, how to sort, which language to answer in. Keyword matching covers it if the classifier is unavailable.

Retrieve

Filters run in a fixed precedence — opening hours first, then proximity with the radius escalating 500 m to 1 km to 2 km until five results exist, then category, then everything else. Rating and popularity only ever affect ranking, never what survives filtering.

Answer

At most five places reach the model, along with the original message. It writes the reply in the language you used and explains why each place matched — distance, rating, opening hours. It cannot search, and it cannot add anything.

What it will not do

  • It will not invent a place. The model only ever sees the candidates retrieval hands it. If a restaurant is not in the index, it cannot appear in an answer.
  • It will not let similarity override geography. Vector search exists as a gated fallback. It never overrules a distance or opening-hours constraint.
  • It will not guess at opening hours. Where the data does not say, the result is labelled unknown rather than assumed open.
  • It will not pad an empty result. Zero matches after full radius escalation produces a clarifying question, not a longer radius quietly applied or a plausible-sounding substitute.

Running it yourself

The backend is a FastAPI service and the client is a Flutter app. Everything runs locally: a GGUF Llama build does the summarising, ChromaDB holds the vectors, and the place index is built from a CSV by one call to the ingest endpoint. No API keys, no cloud inference.

Setup, the endpoint list and the full retrieval specification are in the repository README and under docs/spec/.

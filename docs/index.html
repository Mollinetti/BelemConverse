Why Belém

BelemConverse answers questions about where to go in Belém do Pará, in Portuguese or English, phrased the way people actually ask them.

In November 2025 Belém hosted COP30, the United Nations climate conference. Tens of thousands of delegates, journalists and visitors arrived in a city most of them had never seen, and they needed what every visitor needs: somewhere open at this hour, somewhere close, somewhere good. Search engines handle that question for São Paulo and Rio much better than they handle it for Belém.

This project is aimed at that gap. BelemConverse reads a curated index of local places (markets, botecos, açaí stands, parks, hotels) and replies in the language you wrote in. A visitor typing English gets English. A resident typing "cadê uma barbearia bacana aqui pertinho?" gets Portuguese, and gets understood.

How an answer gets made, and where the model isn't

Almost everything here is plain code on a free server. Reading the question, filtering and ranking places, suggesting follow-ups, paging through more results and the fallback answer all run without a language model. A hosted model is called at most once per question, only to put the top five places into a friendly paragraph. With the model switched off, the site still answers every question.

What each part costs
Checks, planning, search, follow-up chipsPlain CPU work on the free Render instance. A TF-IDF classifier and keyword rules read the question; filters run over a SQLite catalog already in memory. $0.
Template answerBuilt by code from the same five places. Used whenever the model is not allowed, fails, or strays. $0, always available.
Model callOne request to a free tier (Google AI Studio, with Groq as backup), at most 250 tokens back. $0, kept there by the limits below.
HostingThe Flutter client on GitHub Pages, the API on Render's free web service. $0.

What keeps the model's bill at zero

  • Refused messages, "see more", empty searches and spent conversations never reach the model.
  • When it is called, it gets the question and five places in a short prompt and answers in 250 tokens at most.
  • The ceilings are 20 messages per visitor every 10 minutes, 4 questions per conversation and 800 model calls a day. Past that, every answer is a template.

What it will not do

  • It will not invent a place. The model only sees the candidates retrieval hands it, and its reply is checked against them. If the reply names anything else, the visitor gets the template answer.
  • Popularity does not override geography. Opening hours, distance and category decide what stays on the list; rating and popularity only reorder it.
  • It will not measure distances from another city. Searching near you works only when you are in Belém. From anywhere else your location is set aside, and a "near me" question gets a notice saying so before it shows places from across the city.
  • It will not guess opening hours. Where the data does not say, the result is labelled unknown instead of assumed open.
  • It will not pad an empty result. If nothing matches once the radius has grown as far as it goes, the visitor gets a message about what to change, not a larger radius applied in silence or a substitute that merely sounds right.

Running it yourself

Try it in your browser. There is nothing to install and no sign-up. A conversation is four questions, with suggested follow-ups and a free "see more" button. If the server has been idle it can take up to a minute to wake up.

Everything runs on free tiers. The backend is a FastAPI service on Render that searches a committed SQLite catalog of about 2,900 Belém places. A small hosted model writes the reply from the top five, and a template answer takes over when the model is unavailable or its daily allowance is spent. The Flutter web client is served from this site.

Setup, deployment and how to build a catalog for another town are in the repository README.
